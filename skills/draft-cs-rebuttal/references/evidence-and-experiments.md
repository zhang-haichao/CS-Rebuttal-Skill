# 证据检查与最小补充实验

## 一、建立可核查的依据

为主要结论记录证据来源及边界，避免形成过长的对外表格。可内部记录：

| 回应编号 | 要回答的疑问 | 可用事实及出处 | 能支持的主张 | 尚不能支持的主张 |
|---|---|---|---|---|

- 区分作者提供的数据、已读论文中的事实和助手的推断。无法读取的附件或模糊截图不能假装已经核验。
- 检查指标方向、单位、样本量、切分、基线版本及评估集合。对新增表格特别检查能否与原表直接比较。
- 对公式核查定义、下标、形状、假设和推导链；不要从“线性层”跳到未经证明的全模型性质。
- 对效率核查设备、批量、精度、预热、计时范围和包含的训练／推理阶段；只列影响结论的条件。
- 对随机实验核查运行次数、随机种子、均值和离散程度。没有有效统计检验时，不能声称统计显著；均值更大不等于结果可靠。
- 对百分比变化明确口径。例如准确率从 80% 到 81% 是增加 1 个百分点，相对增加 1.25%。核对四舍五入，避免夸大。
- 对新结果区分：支持、部分支持、不支持或暂不可判断。解释的是结果能支撑什么，不是如何把结果写得最好看。

## 二、把补实验限制在真正需要的范围

按以下次序判断：原文是否已有答案 → 重新分析现有结果是否足够 → 是否需要新的控制实验 → 是否超出当前截止时间。

| 优先级 | 适用条件 | 应交付内容 |
|---|---|---|
| 必须解决 | 影响核心正确性、主要比较有效性或共同关键疑虑 | 可执行验证；若做不到，明确缺口及影响 |
| 优先补充 | 能显著增强主要论点，且不耽误必须解决项 | 最小对照与简洁结果 |
| 有余力再做 | 影响次要主张，耗时低 | 辅助分析或简短澄清 |
| 留待后续 | 需新数据、大规模工程或可靠完成时间不足 | 当前范围说明与后续方案 |

不要因一条意见难解决就降级其严重性。安排的是工作顺序与资源，不能让不可完成的核心缺陷从回应中消失。

对每个建议实验写清：

1. 它回答哪一条问题，以及什么结论可能被证伪。
2. 最小可行对照，包括必要的数据划分、预算匹配、基线、指标与重复设置。
3. 正向、负向或不确定结果分别意味着什么；不要预设期望结果。
4. 已知的耗时条件与停止点。未知时给条件式估计，不虚构 GPU 小时。
5. 未完成时能诚实使用的已有证据与表述。

不要通过改种子、改划分、丢弃失败运行或只汇报最好结果追求有利结论。若确需修正协议，记录变化及比较范围；缺少信息时向作者询问，不自动作不当推断。

## 三、常见担忧与合适控制

| 审稿关切 | 可考虑的最小验证 | 必须保留的区别 |
|---|---|---|
| 只是参数更多 | 参数相近的合理控制模型 | 参数量、FLOPs、训练预算并非同一变量 |
| 只是多训了更久 | 固定训练预算或性能—预算关系 | 相同步数不必然是相同计算成本 |
| 增益来源不明 | 移除／替换关键组件的消融 | 消融需避免同时改变多个因素 |
| 缺少强基线 | 同协议下的相关基线 | 他人论文数字不等于可直接比较的重跑结果 |
| 随机性太大 | 适当重复与不确定性报告 | 不把单次结果和多次均值混合排序 |
| 数据泄漏 | 审计数据流、划分及拟合过程 | 清除泄漏后可能必须重跑，不能仅改文字 |
| 泛化性不足 | 对应主张的分布或任务变化 | 更多同分布测试不自动验证外推 |
| 效率收益存疑 | 同硬件和口径的成本测量 | 理论复杂度与真实耗时分别解释 |

## 四、接收新结果后更新回复

- 先读取实验设置，再读取指标，不以期望结论筛选结果。
- 检查新增结果是否真正对应此前的疑虑，是否引入新的混淆因素。
- 当两份材料冲突时定位到具体条目，优先请求澄清；不要任意选有利版本。
- 替换相应英文草稿中的占位符，修改受影响的结论、摘要式开头和其他 reviewer 回复。
- 检查计划与完成状态，去除过期的“将进行实验”或不实的“已修改”。
- 若仅剩语言润色，不继续追加新实验；若还有实质缺口，明确指出最必要的一项。

需要作者补结果时，按当前问题询问：完成状态、设置及对照、指标与数值、重复次数和不确定性、异常结果、允许作出的修改。不要强制用户填写固定表单才能继续。
